🔑 Public Key Infrastructure D3 · 2 videos
Core: Asymmetric pair — public key encrypts → private key decrypts (confidentiality). Private key signs → public key verifies (authenticity + non-repudiation). You never share the private key.
  • CA issues/signs certificates (X.509). RA verifies identity before issuance. CRL/OCSP check revocation (OCSP = real-time; stapling = CA responds less).
  • Certificate lifecycle: enrollment → issuance → validation → revocation → renewal. Key escrow = key held in escrow for recovery; M of N control.
  • Trust models: single CA, hierarchical CA (root → intermediate → leaf; most common), cross-certification, bridge CA, web of trust (PGP).
  • Hybrid encryption: asymmetric to exchange a symmetric session key, symmetric for bulk data (TLS does exactly this).
Trap: Digital signature = hash the message, encrypt hash with sender's PRIVATE key. Confidentiality uses the recipient's PUBLIC key. Non-repudiation only comes from asymmetric signatures.

🔒 Transport Layer Security D4 · 2 videos
TLS 1.2 handshake order: 1) ClientHello (supported ciphers + random) → 2) ServerHello + certificate + ServerHelloDone → 3) Client verifies cert, sends key exchange material → both derive session (symmetric) key → 4) ChangeCipherSpec + Finished. TLS 1.3: fewer round trips, RSA key exchange removed (forward secrecy only).
  • Asymmetric (RSA/ECDHE) only to authenticate & exchange keys; all bulk data = symmetric (AES-GCM).
  • Handshakes: TLS handshake (connection) ≠ TCP 3-way handshake (SYN/SYN-ACK/ACK underneath).
Trap: "Two different handshakes, two different keys" — TCP handshake establishes the connection, TLS handshake establishes encryption. Session keys are symmetric; certificates are asymmetric.

📱 Mobile Security no dedicated video — exam essentials
  • Device security: full-device encryption, screen lock + strong auth, remote wipe, MDM/UEM enrollment, containerization (work profile separated from personal).
  • BYOD risks: data ownership, support ownership, patching responsibility — mitigate with containers + MDM policies, not total bans.
  • App stores / sideloading: only official stores; sideloading bypasses vetting. App signing verifies publisher.
  • Comms: certificate pinning stops MITM via rogue CAs; disable Bluetooth/WiFi auto-connect; COPE vs CYOD vs BYOD ownership models.
  • Attacks: Bluejacking (send message), Bluesnarfing (steal data), Bluebugging (take control); SMiShing, malicious QR codes.
Trap: Remote wipe on BYOD — company container wiped, personal data debate. Bluejacking = harmless message; Bluesnarfing = data theft.

🎫 Hard Tokens D5 · 1 video
  • Something you have — factors: Type 1 = something you know (password/PIN), Type 2 = have (token/card), Type 3 = are (biometrics). Strongest = multifactor combining types.
  • Synchronous dynamic tokens: clock/time-based (RSA SecurID — token + server share a clock/seed) or counter-based (event-sync). Asynchronous: challenge-response (server sends challenge, token computes response).
  • Smart card = token + embedded chip (can process/store certs); memory card = storage only. Smart card + PIN = two factors (have + know).
Trap: Password + PIN = same factor (knowledge) — NOT multifactor. Smart card reader + PIN = 2 factors.
🎓 Security Awareness Training D6 PQ
  • Awareness = "know it exists" (posters, phishing sims) · Training = teach skills for a role · Education = deep, career-level (degree). Ladder: awareness → training → education.
  • Purpose: reduce human-error risk (the #1 attack vector — social engineering/phishing). Metrics: click rates on simulated phishes, report rates.
  • Must be recurring, role-appropriate, and cover: social engineering, password hygiene, data handling/classification, incident reporting duty.
Trap: "Security awareness" is for ALL employees; specific role training is separate. Awareness doesn't create skills — training does.
🧭 Need-to-Know & Least Privilege D5 · 1 video
Need-to-know = even WITH clearance, you get data only if your job requires that specific data. Least privilege = minimum permissions needed to do the job, nothing more. Separation of duties = no single person controls a full critical process (initiate + approve split). Job rotation & mandatory vacations = detective controls against fraud.
Trap: Clearance ≠ need-to-know. Least privilege is enforced via RBAC/ABAC defaults-deny. "Privilege creep" = accumulated permissions over time → fix with periodic access reviews (recertification).

🕵️ Privacy topics (PIA, PbD, Protecting Privacy) D1/D2
  • Privacy by Design — 7 principles: proactive not reactive; privacy as default; embedded in design; full functionality (positive-sum); end-to-end security; visibility & transparency; respect user privacy.
  • PIA = structured assessment run when PII processing changes; data inventory → lawful basis → risks → mitigations → sign-off → re-review.
  • Data states: in transit (TLS/IPSec), in use (compute memory), at rest (encryption). U.S. laws: sectoral (HIPAA health, GLBA financial, FERPA education, COPPA children) — no single federal privacy law; EU GDPR = comprehensive.
  • PII vs IP: PII = personal data about people; IP = intellectual property owned by organizations. Different protection drivers (privacy vs property).
