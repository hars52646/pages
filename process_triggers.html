CISSP Process Triggers

Each process: big picture → one running example → what happens at each step → exam trigger phrases → the mapping table. Read the trigger tables last; they're the exam-day skill: "the question describes a situation → you name the step."
🔁 Change & Configuration Management the "library version changed" family
CONFIGURATION MANAGEMENT (umbrella: control the system's config) ├─ Identification "what do we have?" → baseline: Payroll v5.0, PG 15, Win2025 ├─ Change Control "may it change?" → no unauthorized modification ├─ Status Accounting "what is where?" → prod 5.1 / test 5.2 / dev 5.3 └─ Audit "does reality match the record?" CHANGE MANAGEMENT (3-part sequence for a change): Request Control → Change Control → Release Control → deploy

Running example: upgrade Payroll v5.0 → v5.1

1. Request Control — "ASK"
HR wants a tax-report feature → formal ticket with priority + cost/benefit ($20k, regulatory value).
Triggers: "user requests modification" · "cost/benefit" · "prioritize requests" → Request Control
2. Change Control — "BUILD + TEST + CONTROL"
Recreate/analyze the need → develop → build test cases (valid/invalid/boundary) → quality control → limit effect on other code (don't break payroll calc or login) → document what/why/who → recertify if major.
Triggers: "develop the modification" · "create and test the solution" · "document code changes" · "limit impact on other code" → Change Control
3. Release Control — "ACCEPT + APPROVE + DELIVER"
Decide what's in release 5.1 (tax report ✅, experiment ❌) → remove debug code/backdoors/test accounts → acceptance testing by end users (HR runs payroll) → archive version → distribute the approved build.
Triggers: "acceptance testing with users" · "remove debug/backdoor code" · "approve for production" · "determine release contents" → Release Control
Configuration functions — the lifecycle watchers
Admin disables a security setting with no ticket → Configuration Control violation. Auditor compares server vs baseline, finds setting off + unknown module → Configuration Audit. "What version is deployed where?" → Status Accounting.

⚖️ Risk Management cycle the "price the risk, pick the treatment" family
Identify assets & value (AV) → Identify threats + vulns → Assess (EF, ARO) → SLE = AV×EF → ALE = SLE×ARO → Evaluate safeguards → Treat (Mitigate/Transfer/Avoid/Accept) → Residual risk accepted by senior mgmt → Monitor (loop)

Running example: ransomware vs the $200k customer-portal server

Value & identify
Server AV $200k; threat: ransomware; vuln: no offline backups.
Triggers: "assign value to asset" · "identify critical assets" → start of the cycle.
Quantify
EF 60% → SLE = 120k; ARO 0.5 → ALE = 60k/yr.
Triggers: any "$ per year" math → SLE = AV×EF; ALE = SLE×ARO.
Treat
DR solution $25k/yr cuts EF to 10% → new ALE 10k → value = 60k−10k−25k = +$25k → implement. No good control? Transfer (cyber insurance). Stop the activity? Avoid. Nothing worth it? Accept — consciously, in writing, by senior mgmt.
Triggers: "should the company implement X?" → safeguard formula · "insurance" → transfer · "cost of control exceeds ALE" → accept · "discontinue the service" → avoid.

🏗️ BCP & BIA the "how long can the business survive" family
Ph1 Scope (senior mgmt champion, committee, priorities) → Ph2 BIA (priorities → risks → likelihood → impact → MTD/RTO/WRT/RPO → resource priority) → Ph3 Continuity strategies (sites, backups fit UNDER MTD) → Ph4 Approval (senior mgmt) + implement + train → Test & maintain (loop)

Running example: FinCo maps its processes

BIA impact step
Trading MTD 1 hr, portal 5 days, payroll 1 week → resources flow to trading first. Portal RPO 6 hrs → nightly vaulting OK; trading RPO ≈0 → mirroring.
Triggers: "maximum tolerable downtime decided" → BIA · "how much data loss is acceptable" → RPO · "time to restore systems" → RTO (+WRT inside MTD).
Strategy step
Hot site (minutes, $$$$) for trading · warm (days, $$$) for portal · cold (weeks, $) for payroll archive. Rule: cheapest site that fits under MTD.
Triggers: "needs recovery within hours" → hot site · "days acceptable" → warm · "hardware pre-installed?" → that's warm vs cold's only difference.

🚨 DRP & Incident Response the "disaster day" family
DRP: Assess → Declare (sr mgmt, criteria) → Contain → Notify → Recover in BIA order → Validate (WRT) → Return → Lessons learned IR: Preparation → Detection & Analysis → Containment → Eradication → Recovery → Lessons Learned

Running example: the same 3 AM ransomware, two lenses

DRP lens
Assess scope → CEO declares → insurer/regulator notified → trading up at hot site (BIA order) → portal from vault → integrity checks → return to primary after rebuild.
Triggers: "who declares" → senior mgmt · "restore which system first" → BIA priority · "before restoring" → contain · "after restoring" → validate (WRT).
IR lens
Virus found → contained (disconnect) → eradicated (drive disposed) → recovery (new image) → …and the step everyone skips: lessons learned.
Triggers: "which step was NOT followed" → Lessons Learned (classic) · "rookie engineer, what next" → consult the IR plan — never decide alone · "capture and record" → evidence preservation (prosecution).

🩹 Patch & Vulnerability Management the "known vuln, unpatched" family
Scan (recurring, authenticated) → Prioritize (severity + exposure + active exploitation) → Test patch (staging) → Deploy (windows / emergency track) → Verify (re-scan) → Report metrics (exceptions → accepted risk)

Running example: the 8-month-old patch

What broke
Breach entered via a vuln patched 8 months ago = the deploy/verify steps never ran, or scanning didn't cover that server (discovery failure).
Triggers: "vulnerability existed with vendor fix" → patch management failure · "unpatchable legacy system" → compensating controls + documented risk acceptance · "deployed ≠ fixed" → verify with re-scan.
Triggers (general): "recurring automated checks for missing updates" → vulnerability scanning · "simulate real attacker" → penetration test · "vendor says their product is secure" → SOC 2 report / audit (not their word).
📡 Continuous Monitoring the "in for 7 months, nobody noticed" family
Define what matters (risk register/BIA) → Centralize logs (SIEM, NTP) → Baseline normal → Alert + tune → 24/7 review → escalation into IR → report posture (loop)

Running example: the watched inbox

What broke
Logs existed, alerts went to an unwatched mailbox, no baseline → detection chain broke at review/tuning, not at collection.
Triggers: "compromised for months unnoticed" → monitoring/response failure · "too many alerts" → tuning / alert fatigue · "detect behavior unlike baseline" → anomaly (statistical) detection · "known attack pattern" → signature detection.
Managerial mindset: monitoring exists to FEED incident response and risk reporting — detection without response is expensive logging.
🏭 Third-Party / Vendor Management the "cloud vendor leaked it" family
Due diligence (SOC 2, history) BEFORE contract → security clauses (SLA, breach notify, right to audit, exit) → least-privilege data sharing → ongoing reassessment → incident coordination → exit with data destruction

Running example: FinCo's SaaS leak

What broke
No due diligence, no clauses, no evidence access. The accountability rule: outsourcing the work never outsources the accountability — FinCo still answers to its regulators.
Triggers: "before engaging a vendor" → due diligence · "vendor assurance report" → SOC 2 (Type II = controls operated over time) · "ensure data destroyed at contract end" → exit clause · "vendor had a breach" → contract breach-notification duty + your own notifications.
🗂️ Data Classification & Handling the "mislabeled spreadsheet leak" family
Classify (by impact) → Define handling per level → Label → Train (incl. contractors) → Enforce (DLP, access controls) → Incident + review

Running example: contractor emails customer records home

What broke
Labeled "internal" instead of "confidential" (classification) + no contractor training (awareness) + no DLP (enforcement). Three processes failed at once — the exam asks which CONTROL would have prevented it: DLP egress monitoring.
Triggers: "how do we decide protection level" → classification by impact · "prevent sensitive data leaving" → DLP · "same rules for contractors?" → yes: training + agreements (NDA) · "military labels" → Top Secret/Secret/Confidential; "commercial" → Confidential/Private/Public.
👥 Personnel Security & Fraud Controls the "clerk stole for 3 years" family
Separation of duties → Dual control → Least privilege + periodic recertification → Job rotation & mandatory vacations (detective) → Onboarding/offboarding access hygiene → Audit trail

Running example: the payments clerk

What broke
He initiated AND approved payments (SoD broken), rights accumulated across roles (no recertification), never took vacation (rotation/vacation would have exposed him), HR didn't trigger revocation at transfer.
Triggers: "one person controls whole transaction" → separation of duties · "detects fraud by absence" → mandatory vacation / job rotation · "access accumulated over years" → privilege creep → periodic access review · "employee left, access remains" → offboarding failure · "password + PIN" → SAME factor, not multifactor.
💻 SDLC Security the "flaw shipped to prod" family
Requirements (security reqs, PIA) → Design (threat model) → Develop (secure coding, reviews) → Test (SAST=code, DAST=running) → Deploy (final review, hardening) → Operate (patch, monitor) → Dispose (sanitize media)

Running example: the SQL injection that shipped

What broke
SQLi in production = design phase never threat-modeled input OR test phase had no DAST/SAST gate OR code review skipped parameterized queries. Cost of fixing grows each phase it survives.
Triggers: "security requirements defined when" → Phase 1, before code · "find flaws in source code" → SAST (static) · "test the running app" → DAST (dynamic) · "risk-driven model" → Spiral · "privacy in the lifecycle" → PIA early (privacy by design) · "system retired" → data sanitization/declassification.
